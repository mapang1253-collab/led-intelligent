# บทนำ (Introduction) — Finca Check

ร่างสำหรับใส่ในรายงาน แบ่งตามหัวข้อมาตรฐานของบทที่ 1 ตัดหัวข้อที่ไม่ต้องใช้ออกได้
ตัวเลขทุกตัวอ่านจากระบบที่ deploy อยู่จริงเมื่อ 9 ตุลาคม 2569 — ก่อนส่งให้ทวนที่หน้า "สถานะระบบ" อีกครั้ง

---

## 1.1 ความเป็นมาและความสำคัญของปัญหา

การตัดสินใจว่าที่ดินแปลงหนึ่งควรนำไปใช้ประโยชน์ในรูปแบบใดจึงจะเหมาะสมที่สุด เป็นคำถามพื้นฐาน
ในวิชาการประเมินมูลค่าทรัพย์สิน ซึ่งเรียกว่าการวิเคราะห์การใช้ประโยชน์สูงสุดและดีที่สุด
(Highest and Best Use) โดยพิจารณาความเป็นไปได้สี่ด้านประกอบกัน ได้แก่ ความเป็นไปได้ทางกฎหมาย
ความเป็นไปได้ทางกายภาพ ความเป็นไปได้ทางการเงิน และการให้ผลตอบแทนสูงสุด

ในทางปฏิบัติ ข้อมูลที่จำเป็นต่อการวิเคราะห์ดังกล่าวมีเผยแพร่อยู่แล้วโดยหน่วยงานภาครัฐของไทย
แต่กระจายอยู่ตามหน่วยงานต่าง ๆ อย่างน้อยห้าแห่ง ดังนี้

| ข้อมูลที่ต้องใช้ | หน่วยงานผู้เผยแพร่ |
|---|---|
| ราคาประเมินทุนทรัพย์ที่ดิน สิ่งปลูกสร้าง และอาคารชุด | กรมธนารักษ์ (เผยแพร่แยกเป็นสามระบบ) |
| ผังเมืองรวมและข้อกำหนดการใช้ประโยชน์ที่ดิน | กรมโยธาธิการและผังเมือง |
| ขอบเขตและรูปแปลงที่ดิน | กรมที่ดิน |
| จำนวนประชากรตามทะเบียนราษฎร | กรมการปกครอง |
| รายได้เฉลี่ยต่อเดือนของครัวเรือน | สำนักงานสถิติแห่งชาติ |

ปัญหาจึงมิได้อยู่ที่การไม่มีข้อมูล หากแต่อยู่ที่ข้อมูลเหล่านี้อยู่คนละระบบ ใช้ชื่อเรียกพื้นที่
หน่วยวัด และปีข้อมูลที่ไม่สอดคล้องกัน ทำให้ผู้ที่มิได้เป็นผู้เชี่ยวชาญไม่สามารถนำมาเทียบเคียง
และประมวลผลร่วมกันได้

นอกจากนี้ บริการเชิงพาณิชย์ที่มีอยู่ในปัจจุบันมุ่งนำเสนอราคาเสนอขายในตลาดเป็นหลัก
ซึ่งเป็นคนละสิ่งกับคำถามว่าที่ดินแปลงนั้น**ทำอะไรได้ตามกฎหมาย** และโดยทั่วไปมิได้แสดง
แหล่งที่มา ปีของข้อมูล หรือข้อจำกัดของชุดข้อมูลที่นำมาใช้ ผู้ใช้จึงไม่สามารถตรวจสอบย้อนกลับได้
ว่าข้อสรุปที่ได้รับตั้งอยู่บนหลักฐานใด

โครงงานนี้จึงพัฒนาระบบที่รวบรวมหลักฐานจากหน่วยงานภาครัฐไว้ในที่เดียว ประมวลผลตามลำดับ
การวิเคราะห์ HBU และ **แสดงขอบเขตของสิ่งที่ข้อมูลตอบได้และตอบไม่ได้อย่างชัดเจน**
ซึ่งเป็นคุณลักษณะที่ผู้วิจัยเห็นว่าสำคัญไม่น้อยกว่าตัวผลลัพธ์

## 1.2 วัตถุประสงค์ของโครงงาน

1. เพื่อพัฒนาระบบที่รวบรวมราคาประเมินของทางราชการ ข้อมูลประชากร ข้อมูลรายได้ครัวเรือน
   และผังเมืองรวมของพื้นที่เป้าหมาย ให้แสดงผลในที่เดียวโดยคงการอ้างอิงแหล่งที่มา
   ปีข้อมูล และข้อจำกัดของทุกรายการไว้ครบถ้วน
2. เพื่อออกแบบกระบวนการวิเคราะห์การใช้ประโยชน์ที่ดิน ซึ่งใช้ปัญญาประดิษฐ์เป็นผู้เสนอแนวคิด
   และใช้ชุดกฎแบบกำหนดผลตายตัว (deterministic) เป็นผู้ตรวจสอบ โดยปัญญาประดิษฐ์
   ไม่มีอำนาจตัดสินความถูกต้องตามกฎหมายและไม่สามารถแก้ผลการตรวจสอบได้
3. เพื่อพัฒนากลไกที่ทำให้ระบบรายงานสถานะ "ยังตรวจสอบไม่ได้" อย่างตรงไปตรงมา
   พร้อมระบุว่าขาดข้อมูลใดและต้องได้มาจากแหล่งใด แทนการประมาณค่าเพื่อให้ผลลัพธ์ดูสมบูรณ์
4. เพื่อให้ระบบสามารถใช้งานได้ครอบคลุมทุกจังหวัดของประเทศไทย โดยไม่ต้องลงทะเบียน
   และไม่จัดเก็บข้อมูลของผู้ใช้ไว้เกินระยะเวลาที่จำเป็น

## 1.3 ขอบเขตของโครงงาน

### 1.3.1 ขอบเขตด้านพื้นที่และข้อมูล

| รายการ | ขอบเขต |
|---|---|
| พื้นที่ที่วิเคราะห์ได้ | 77 จังหวัด 928 อำเภอ 7,436 ตำบล ทั่วประเทศ |
| ข้อมูลที่เปิดใช้งานแล้ว | 74,052 รายการ จาก 5 ชุดข้อมูล |
| การค้นแปลงที่ดินด้วยระวางและเลขที่ดิน | 58 จังหวัด |
| ชุดกฎหมายที่ใช้ตรวจสอบ | กฎกระทรวง ฉบับที่ 55 (พ.ศ. 2543) เฉพาะหมวดที่ว่าง แนวอาคาร และระยะร่น จำนวน 15 ข้อ |
| ระดับของผลลัพธ์ | ระดับพื้นที่ (ตำบล) มิใช่ระดับรายแปลง |

ชุดข้อมูลที่เปิดใช้งานทั้งห้าชุด ได้แก่ สถิติจำนวนประชากรตามทะเบียนราษฎร (21,678 รายการ)
รายได้เฉลี่ยต่อเดือนของครัวเรือน (1,540 รายการ) ราคาประเมินสิ่งปลูกสร้าง (5,313 รายการ)
ราคาประเมินอาคารชุด (13,550 รายการ) และราคาประเมินทุนทรัพย์ที่ดินประเภทอื่น (31,971 รายการ)

### 1.3.2 ขอบเขตด้านเทคโนโลยี

ส่วนติดต่อผู้ใช้พัฒนาด้วย React 19 และ Vite ส่วนประมวลผลฝั่งเซิร์ฟเวอร์ใช้ Hono บน
Cloudflare Workers ฐานข้อมูลใช้ Supabase PostgreSQL ร่วมกับส่วนขยาย PostGIS เชื่อมต่อผ่าน
Hyperdrive และใช้แบบจำลองภาษา `gemini-3.1-flash-lite` ในการเสนอแนวคิดการใช้ประโยชน์ที่ดิน
โดยจำกัดการเรียกใช้ไม่เกิน 2 ครั้งต่อการวิเคราะห์หนึ่งครั้ง

### 1.3.3 สิ่งที่อยู่นอกขอบเขต

โครงงานนี้**ไม่ครอบคลุม**รายการต่อไปนี้ โดยแต่ละข้อเป็นผลจากการตัดสินใจเชิงออกแบบที่บันทึกไว้
มิใช่งานที่ยังทำไม่เสร็จ

1. **การประเมินมูลค่าทรัพย์สินรายแปลง** ระบบให้ผลระดับพื้นที่ เนื่องจากยังไม่มีแหล่งข้อมูล
   รายแปลงที่เข้าถึงได้ตามสิทธิ์
2. **คำแนะนำการลงทุน** ผลลัพธ์เป็นการคัดกรองเบื้องต้นเชิงวิชาการ มิใช่คำรับรองทางกฎหมาย
   วิศวกรรม การสำรวจ การประเมินราคา หรือคำแนะนำการลงทุน
3. **ข้อมูลการขายทอดตลาดของกรมบังคับคดี** ผู้วิจัยได้ศึกษาแหล่งข้อมูลนี้แล้วและตัดสินใจไม่นำมาใช้
   ด้วยเหตุผลสามประการ ได้แก่ เงื่อนไขสิทธิ์การใช้งานที่ระบุห้ามทำซ้ำหรือดัดแปลง
   ประเด็นข้อมูลส่วนบุคคลตามพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล เนื่องจากประกาศขายทอดตลาด
   ปรากฏชื่อคู่ความและเจ้าของทรัพย์ และการที่ระบบค้นหามีมาตรการป้องกันการเข้าถึงอัตโนมัติ
   ซึ่งโครงงานนี้ถือหลักว่าจะไม่หลีกเลี่ยง
4. **การคำนวณความเป็นไปได้ทางการเงิน** ส่วนประกอบทางเศรษฐศาสตร์ยังไม่ผ่านเกณฑ์การตรวจทาน
   สถานะผลลัพธ์สุดท้ายจึงเป็น "หลักฐานไม่เพียงพอ" ในทุกกรณี ซึ่งเป็นพฤติกรรมที่ถูกต้องตามการออกแบบ
5. **การส่งออกผลลัพธ์เป็นไฟล์ การแชร์สาธารณะ และการเก็บประวัติย้อนหลัง** ผลลัพธ์แสดงบนหน้าเว็บ
   เท่านั้น และถูกลบอัตโนมัติภายใน 24 ชั่วโมง

## 1.4 ประโยชน์ที่คาดว่าจะได้รับ

1. ผู้ที่ถือครองที่ดินหรือกำลังพิจารณาที่ดินสามารถเห็นราคาประเมินของทางราชการ ผังเมืองรวม
   และข้อกำหนดทางกฎหมายของพื้นที่นั้นได้จากจุดเดียว โดยไม่ต้องสืบค้นจากหลายหน่วยงาน
2. ผู้ใช้ทราบขอบเขตของข้อสรุปที่ได้รับ เนื่องจากระบบระบุแหล่งที่มา ปีข้อมูล และข้อจำกัด
   ของทุกตัวเลข พร้อมแจ้งประเด็นที่ข้อมูลยังไม่เพียงพอต่อการสรุปผล
3. ได้ต้นแบบสถาปัตยกรรมที่แยกบทบาทระหว่างปัญญาประดิษฐ์ในฐานะผู้เสนอ กับชุดกฎแบบกำหนด
   ผลตายตัวในฐานะผู้ตรวจสอบ ซึ่งสามารถนำไปประยุกต์กับงานที่ต้องการความสามารถ
   ในการตรวจสอบย้อนกลับได้ในสาขาอื่น
4. ได้บันทึกการตัดสินใจเชิงสถาปัตยกรรมและเหตุผลด้านสิทธิ์การใช้ข้อมูลและการคุ้มครอง
   ข้อมูลส่วนบุคคล ซึ่งเป็นประโยชน์ต่อผู้ที่จะพัฒนาระบบลักษณะเดียวกันต่อไป

## 1.5 นิยามศัพท์เฉพาะ

| คำ | ความหมายที่ใช้ในโครงงานนี้ |
|---|---|
| **การใช้ประโยชน์สูงสุดและดีที่สุด** (Highest and Best Use) | การใช้ประโยชน์ที่ดินที่เป็นไปได้ทั้งทางกฎหมาย ทางกายภาพ และทางการเงิน และให้ผลตอบแทนสูงสุด |
| **ราคาประเมินทุนทรัพย์** | ราคาที่กรมธนารักษ์กำหนดเพื่อใช้ในการจัดเก็บภาษีและค่าธรรมเนียม มิใช่ราคาซื้อขายในตลาด |
| **หลักฐาน** (Evidence) | ค่าที่หน่วยงานเผยแพร่จริงหนึ่งรายการ พร้อมข้อมูลกำกับว่ามาจากแหล่งใด ปีใด เป็นของกลุ่มใด และห้ามนำไปใช้แทนสิ่งใด |
| **สถานะการตรวจสอบ** | ผลการตรวจกฎแต่ละข้อ มีสี่สถานะคือ ผ่าน (PASS) ไม่ผ่าน (FAIL) ผ่านบางส่วน (PARTIAL) และยังตรวจไม่ได้ (UNKNOWN) โดยสถานะ UNKNOWN ไม่สามารถแปลงเป็น PASS หรือ FAIL ได้ |
| **ขอบเขตของผลลัพธ์** | ระดับความเฉพาะเจาะจงของข้อสรุป แบ่งเป็นระดับพื้นที่ (AREA) ระดับทรัพย์สินเบื้องต้น (PRELIMINARY_PROPERTY) และระดับทรัพย์สิน (PROPERTY) ซึ่งระบบปัจจุบันให้ผลที่ระดับ AREA |
| **ACADEMIC_REVIEWED** | สถานะวงจรชีวิตของชุดกฎหรือวิธีคำนวณที่ผ่านการตรวจทานเชิงวิชาการและบันทึกชื่อผู้ตรวจไว้แล้ว มิใช่การรับรองระดับวิชาชีพ ระบบจะประมวลผลเฉพาะชุดที่มีสถานะนี้ |

## หมายเหตุสำหรับผู้เขียนรายงาน

- หัวข้อ 1.3.3 ข้อ 3 (กรมบังคับคดี) และข้อ 4 (การคำนวณทางการเงิน) เป็นสองจุดที่กรรมการ
  มักตั้งคำถาม การเขียนไว้ในบทนำตั้งแต่ต้นจะได้เปรียบกว่าการถูกถามแล้วค่อยอธิบาย
- หากรายงานกำหนดให้มีสมมติฐานการวิจัย (Hypothesis) โครงงานนี้เป็นงานพัฒนาระบบ
  จึงควรใช้หัวข้อ "คำถามของโครงงาน" แทน เช่น *ระบบที่รายงานขอบเขตของความไม่รู้อย่างตรงไปตรงมา
  จะให้ประโยชน์แก่ผู้ใช้มากกว่าระบบที่ประมาณค่าเพื่อให้ผลลัพธ์ดูสมบูรณ์หรือไม่*
