## 3 · สคริปต์สาธิตสด

### เตรียมก่อนขึ้นเวที

- **ห้ามเตรียมลิงก์ผลลัพธ์ไว้ล่วงหน้าข้ามคืน** ผลลัพธ์หมดอายุ **24 ชั่วโมงพอดี** และสิทธิ์เข้าถึง
  ผูกกับ cookie ของเครื่องนั้น เปิดคนละเครื่องก็เข้าไม่ได้ ต้องกดรันสดหน้างาน
- เปิดหน้าเว็บทิ้งไว้ก่อน 1 แท็บ และเปิดหน้า "สถานะระบบ" ไว้อีกแท็บ
- รันหนึ่งครั้งใช้เวลาประมาณ **70–80 วินาที** เตรียมบทพูดคลุมช่วงรอไว้ (ใช้ช่วงนี้พูดหัวข้อ 4 ได้เลย)
- **เปิดเว็บทิ้งไว้ล่วงหน้าอย่างน้อย 5 นาทีก่อนขึ้นเวที** คำขอแรกหลังเว็บไม่ถูกใช้งานมานานเป็น cold start
  ซึ่งวัดได้จริงที่ **32 วินาที** (ครั้งถัดไปเหลือ 2 วินาที) ถ้าเปิดสด ๆ หน้าเวทีจะดูเหมือนเว็บค้าง
- เผื่อแผน B: ถ้าเน็ตมีปัญหา ใช้ภาพหน้าจอที่เตรียมไว้ และ [`docs/demo-valuation-bangphun.md`](demo-valuation-bangphun.md) ซึ่งมีตัวเลขจริงทุกช่องของแท็บประเมินมูลค่า

## 4 · จุดแข็งเชิงวิชาการ 5 ข้อ

พูดให้ครบ 5 ข้อนี้ เพราะเป็นสิ่งที่เว็บอสังหาทั่วไปไม่ทำ

1. **ทุกตัวเลขสืบกลับได้** — แต่ละตัวเลขพกหน่วยงานต้นทาง ปีข้อมูล กลุ่มประชากรที่ครอบคลุม
   ระดับพื้นที่ และ "ข้อจำกัด: ห้ามใช้แทน..." ของแหล่งนั้นติดตัวไปด้วยเสมอ

2. **ความมั่นใจต้องไม่เกินหลักฐาน** — ผลลัพธ์แบ่งระดับเป็น `AREA` / `PRELIMINARY_PROPERTY` /
   `PROPERTY` ตอนนี้ทุก run อยู่ที่ `AREA` เพราะยังไม่มีแหล่งข้อมูลรายแปลง ระบบจะไม่ยกระดับให้ตัวเอง

3. **AI เสนอ · เครื่องยนต์ตรวจ · AI ไม่มีสิทธิ์ตัดสิน** — AI เสนอแนวคิดการใช้ประโยชน์เท่านั้น
   ส่วนการตรวจกฎหมายเป็นตัวตรวจแบบ deterministic ที่อ่านจากชุดกฎที่ผ่านการตรวจทานแล้ว
   AI แก้ผลตรวจไม่ได้ และห้ามคิดสูตรคำนวณเอง

4. **"ไม่รู้" ไม่เท่ากับ "ไม่ผ่าน"** — ผลตรวจมี 4 สถานะ `PASS / FAIL / PARTIAL / UNKNOWN`
   และระบบถูกออกแบบให้แปลง UNKNOWN เป็น PASS หรือ FAIL **ไม่ได้เด็ดขาด** มีเทสต์ล็อกไว้ด้วยซ้ำ
   ว่าถ้าผู้ใช้พิมพ์ตัวเลขเข้ามาเอง ตัวเลขนั้นเลือกได้แค่ว่า "กฎข้อไหนเกี่ยวข้อง" แต่ตัดสิน
   "ผ่าน/ไม่ผ่าน" ไม่ได้ (บันทึกไว้ใน [`docs/adr/0010`](adr/0010-stated-building-scale-scopes-rules-only.md))

5. **รันได้เฉพาะของที่ผ่านการตรวจทานแล้ว** — ชุดกฎและวิธีคำนวณมีสถานะ `ACADEMIC_REVIEWED`
   พร้อมชื่อผู้ตรวจและวันที่บันทึกถาวร ถ้าไม่ผ่านสถานะนี้ ระบบจะไม่เอามารัน
   (ย้ำว่า "ตรวจทานเชิงวิชาการ" ไม่ใช่การรับรองระดับวิชาชีพ)

## 5 · สิ่งที่ยังไม่ทำ — พูดเองก่อนถูกถาม

นี่คือส่วนที่จะทำให้ได้คะแนนหรือเสียคะแนน **วิธีพูดสำคัญกว่าตัวเนื้อหา**

### 5.1 ผลตรวจกฎหมายส่วนใหญ่ขึ้นว่า "ยังตรวจไม่ได้"

**อย่าพูดว่า** "ระบบยังทำไม่เสร็จ"

**ให้พูดว่า** ชุดกฎที่ใช้คือกฎควบคุม**อาคาร** ซึ่งถามว่า "อาคารหลังนี้ร่นจากถนนกี่เมตร สูงเท่าไหร่
เว้นที่ว่างเท่าไหร่" แต่สิ่งที่ผู้ใช้เอามาให้คือ **ที่ดินเปล่าที่ยังไม่มีแบบ** ค่าเหล่านั้นจึงยังไม่มีอยู่จริง
ระบบเลือกที่จะตอบว่า "ยังตรวจไม่ได้ และนี่คือสิ่งที่ต้องไปเอามา" แทนที่จะเดาให้ดูสวย

ชี้ที่กรอบบนหน้าจอที่สรุปให้ว่าต้องไปเอาอะไรมาจากไหน เช่น "แบบผังบริเวณ — 4 ข้อกำหนด"
แล้วบอกว่า **ถ้ากรอกความกว้างถนนกับขนาดอาคารที่ตั้งใจเข้าไป กฎจาก 4 ข้อที่ยังตัดสินไม่ได้
จะเหลือข้อเดียวที่เกี่ยวข้องจริง พร้อมบอกว่าต้องร่นกี่เมตร** — สาธิตให้ดูได้เลย

### 5.2 สถานะสุดท้ายขึ้นว่า "หลักฐานไม่เพียงพอ" ทุกครั้ง

ระวังอย่าพูดว่า "คำนวณการเงินไม่ได้" เพราะ**คำนวณได้** — แท็บประเมินมูลค่ามีเครื่องคำนวณ
ระยะเวลาคืนทุนและอัตราผลตอบแทน ใช้ชุดวิธี `th.feasibility.assumption` ที่ตรวจทานแล้ว และสาธิตสดได้

ที่ยังไม่เปิดใช้งานคือการดึงตัวเลขเหล่านั้น**จากหลักฐานเอง** เครื่องคำนวณรับสมมติฐานที่ผู้ใช้กรอก
และสมมติฐานของผู้ใช้ไม่มีผลต่อสถานะสุดท้าย ระบบจึง**ห้ามตัวเอง**ไม่ให้สรุปว่า "ควรสร้าง X" —
ถ้าแก้ให้มันสรุปจากตัวเลขที่ผู้ใช้กรอกเอง จะเป็นการนำเสนอสมมติฐานของผู้ใช้เป็นข้อค้นพบของระบบ

### 5.3 ไม่มีปุ่มดาวน์โหลด PDF / ส่งออก / แชร์ / ประวัติย้อนหลัง

**เป็นการตัดสินใจเชิงออกแบบ ไม่ใช่ฟีเจอร์ที่ลืมทำ** ผลลัพธ์เป็นการศึกษาเบื้องต้นเชิงวิชาการ
ถ้าให้ดาวน์โหลดเป็นไฟล์ ไฟล์นั้นจะหลุดจากบริบทและข้อจำกัดที่แสดงไว้ และอาจถูกเอาไปใช้
เหมือนรายงานประเมินราคาจริง จึงจงใจให้ดูได้เฉพาะบนหน้าเว็บที่มีคำเตือนกำกับ และลบทิ้งใน 24 ชั่วโมง

## 6 · สถาปัตยกรรมโดยย่อ (ถ้าต้องพูด 1 นาที)

```text
รับข้อมูลที่ดิน → ระบุพื้นที่ → รวบรวมหลักฐานจากแหล่งที่ผ่านการอนุมัติ
  → AI เสนอแนวคิด (มีโครงสร้าง ตรวจ schema ทุกครั้ง)
  → ตรวจกฎหมายแบบ deterministic → ตัดสินสถานะสุดท้าย → แสดงผลภาษาไทย
```

- **หน้าเว็บ:** React 19 + Vite · **หลังบ้าน:** Hono บน Cloudflare Workers · **ฐานข้อมูล:** Supabase PostgreSQL/PostGIS
- **AI:** Gemini (`gemini-3.1-flash-lite`) เรียกได้สูงสุด 2 ครั้งต่อ 1 run (ปกติ 1 + ซ่อม 1)
- ไม่มีระบบสมาชิก ไม่ต้องล็อกอิน แต่ละ run แยกขาดจากกันและลบอัตโนมัติใน 24 ชั่วโมง

## 7 · คำถามที่น่าจะโดนถาม พร้อมคำตอบ

| คำถาม | ตอบว่า |
|---|---|
| ข้อมูลเอามาจากไหน เชื่อถือได้ไหม | 5 แหล่งจากหน่วยงานรัฐโดยตรง — กรมการปกครอง สำนักงานสถิติแห่งชาติ กรมธนารักษ์ กรมที่ดิน กรมโยธาธิการและผังเมือง ทุกรายการบอกปีข้อมูลและหน่วยงานได้ ตรวจได้ที่หน้า "สถานะระบบ" |
| ใช้ AI ทำอะไรบ้าง | เสนอแนวคิดการใช้ประโยชน์ที่ดินเท่านั้น ไม่ได้ตัดสินกฎหมาย ไม่ได้คำนวณเงิน ไม่ได้แต่งตัวเลข และผลจาก AI ต้องผ่านการตรวจ schema กับภาษาไทยก่อนขึ้นจอ |
| **ตอนนี้เรียก AI จริงหรือเปล่า** | ตอบตรง ๆ ว่าเวอร์ชันที่ deploy ตั้งเป็นโหมด `RECORDED_AI` คือเล่นคำตอบที่บันทึกไว้ซ้ำ เพื่อให้สาธิตได้เสถียรและไม่เปลืองโควตา ส่วนโหมดเรียกจริง (`LIVE_AI`) ใช้ตอนพัฒนา และหน้าจอ "สถานะระบบ" บอกโหมดที่ใช้อยู่ตามจริงเสมอ **อย่าพูดว่าเรียกสดถ้าไม่ได้เรียก** |
| ทำไมไม่บอกไปเลยว่าควรสร้างอะไร | ดูข้อ 5.2 — ตัวเลขการเงินมาจากสมมติฐานของผู้ใช้ ไม่ใช่จากหลักฐาน จึงไม่มีสิทธิ์สรุป |
| ทำไมผลตรวจกฎหมายเป็น "ยังตรวจไม่ได้" เยอะ | ดูข้อ 5.1 — กฎถามเรื่องอาคาร แต่ input เป็นที่ดินเปล่า |
| แม่นแค่ไหน เอาไปซื้อขายจริงได้ไหม | ไม่ได้ และระบบบอกเองทุกหน้าจอ เป็นเครื่องมือ**คัดกรองก่อนลงทุน**ระดับพื้นที่ ไม่ใช่รายแปลง ก่อนตัดสินใจจริงต้องตรวจกับผู้เชี่ยวชาญ |
| ต่างจาก DDproperty / Baania อย่างไร | เว็บเหล่านั้นบอก "ราคาตลาดของประกาศขาย" เราบอก "ที่ดินนี้ทำอะไรได้ตามกฎหมาย และหลักฐานที่มีบอกอะไรได้บ้าง" พร้อมบอกจุดที่ข้อมูลยังไม่พอ |
| ถ้าข้อมูลไม่ครอบคลุมพื้นที่ที่ค้น | ระบบบอกว่า "ไม่มีข้อมูล" ไม่ใช่ "ไม่มีมูลค่า" และจะไม่เอาข้อมูลพื้นที่อื่นมาสวมแทน |
| ทำต่อได้อีกไหม | ได้ 3 ทาง — เปิดใช้ส่วนคำนวณการเงิน, ทำชุดกฎผังเมืองรวมให้ตรวจได้จริง (ตอนนี้แสดงเป็นบริบทแล้วแต่ยังไม่ใช่กฎที่ตรวจ), และขยายข้อมูลรายแปลงให้ยกระดับจาก AREA เป็น PROPERTY |
