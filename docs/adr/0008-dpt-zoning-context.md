# ADR 0008 — แสดงผังเมืองรวมเป็นบริบทประกอบ ไม่ใช่ผลการตรวจสอบ

- สถานะ: Accepted
- วันที่: 2026-09-26
- ผู้ตัดสินใจ: เจ้าของโปรเจกต์ (อรณภา, สุรัตนาพร)
- เกี่ยวข้องกับ: [ADR 0001](0001-first-increment-scope.md) (ขอบเขต increment แรก),
  [ADR 0006](0006-map-pin-and-osm-proximity.md) (หมุดบนแผนที่และบริบทที่ไม่ใช่หลักฐาน),
  [`docs/implementation-plan.md`](../implementation-plan.md) §4 (activation gate),
  [`docs/output-policy.md`](../output-policy.md)

## บริบท

เจ้าของโปรเจกต์ขอให้ระบบ "แสดงผังเมือง สีของผังเมือง ว่าที่ดินตรงนั้นจะสามารถทำอะไรได้บ้าง"

ก่อนหน้านี้ระบบไม่มีข้อมูลผังเมืองเลย และ `docs/output-policy.md` เองก็นับ
`ผังเมืองรวมและการใช้ประโยชน์ที่ดิน` เป็น **unscreened domain** — คือโดเมนที่ชุดกฎ `th.cba.mr55`
ไม่ได้ตรวจ จึงต้องรายงานเป็น `BLOCKING` และห้ามถือว่าผ่าน (ดู `final-status.test.ts`
"flags a domain the pack does not screen as blocking, never as passed")

การตรวจสอบเมื่อ 2026-09-26 พบว่ากรมโยธาธิการและผังเมืองเปิดเผยข้อมูลนี้จริงผ่านบริการสาธารณะสองตัว
ที่ตอบคนละครึ่งของคำถาม และต้องเรียกทั้งคู่ (รายละเอียดการเข้าถึงอยู่ใน
[`docs/data-sources/dpt-zoning.md`](../data-sources/dpt-zoning.md))

## ปัญหา

"ที่ดินตรงนี้เป็นที่ดินประเภทอะไร" กับ "ที่ดินตรงนี้สร้างอะไรได้" เป็นคนละคำถาม แต่ผู้อ่านจะอ่านรวมเป็นคำถามเดียว

ผังเมืองบอกว่าที่ดินประเภทหนึ่ง ๆ มีไว้เพื่ออะไร แต่ไม่ได้แปลว่าสิ่งที่ผู้อ่านจะสร้าง ทำได้จริงบนแปลงนั้น —
ยังมีบัญชีท้ายกฎกระทรวงกำกับอีกชั้น มีกฎหมายควบคุมอาคาร และมีสภาพแปลง (หน้ากว้าง ทางเข้าออก ภาระจำยอม)
เป็นตัวตัดสินที่เหลือ การเอาผลค้นผังเมืองมาแสดงว่า "ทำได้" จึงเป็นการเลื่อนหลักฐานระดับพื้นที่ให้กลายเป็น
หลักฐานระดับทรัพย์สิน ซึ่งเป็นสิ่งที่ผลิตภัณฑ์นี้ถูกสร้างมาเพื่อปฏิเสธ

## การตัดสินใจ

แสดงผังเมืองเป็น **บริบทที่มีการอ้างอิง (context with a citation)** อยู่นอกขั้นตอนการวิเคราะห์ทั้งหมด
ให้สถานะเดียวกับ OSM proximity ใน ADR 0006:

1. **ไม่สร้าง `Observation` และไม่สร้าง `EvidenceLink`** จึงไม่ต้องผ่าน activation gate ของแหล่งหลักฐาน
   ใน `docs/implementation-plan.md` §4 — เพราะ gate นั้นคุมสิ่งที่เข้าสู่การวิเคราะห์ และสิ่งนี้ไม่เข้า
2. **เปลี่ยน validation status หรือ output scope ไม่ได้** `permitted_scope` ยังคงเป็น `AREA`
   สถานะของกฎยังเป็น `PASS | FAIL | PARTIAL | UNKNOWN` ตามเดิม และ
   `ผังเมืองรวมและการใช้ประโยชน์ที่ดิน` **ยังคงเป็น unscreened domain แบบ BLOCKING เหมือนเดิม**
   การเห็นชื่อโซนบนหน้าจอไม่ได้ทำให้โดเมนนั้นถูกตรวจแล้ว
3. **คัดข้อความจากกรมฯ มาแสดงตรง ๆ ไม่เรียบเรียงใหม่ ไม่สรุป ไม่ตีความ** และบอกบนหน้าจอว่าเป็นข้อความที่คัดมา
   ข้อกำหนดและข้อห้ามแสดงคู่กันเสมอ ไม่พับข้อห้ามซ่อนไว้
4. **สีที่แสดงเป็นสีของกรมฯ เอง** อ่านจาก renderer ของชั้นข้อมูล และชั้นซ้อนบนแผนที่ใช้ภาพที่กรมฯ วาดเอง
   ไม่ได้ทำจานสีขึ้นใหม่ให้ดูคล้าย
5. **คืนทุกผังที่ครอบคลุมจุดนั้น ไม่เลือกให้** หลายจังหวัดมีทั้งผังจังหวัดและผังเมือง/ชุมชนทับกัน
   (เช่น สันทราย เชียงใหม่ คืนสองผัง) ว่าผังใดมีผลบังคับเหนือกว่าเป็นคำถามทางกฎหมายที่ระบบนี้ยังไม่มีกฎรองรับ
   การเลือกให้เงียบ ๆ คือการให้ความเห็นทางกฎหมายโดยไม่มีอำนาจ

## ผลที่ตามมา

**ได้:** ผู้อ่านเห็นว่าที่ดินอยู่ในโซนอะไร สีอะไร หมายเลขบริเวณใด ข้อกำหนดว่าอย่างไร และห้ามอะไรบ้าง
ซึ่งเป็นคำถามแรกที่คนดูที่ดินถาม และเดิมระบบตอบไม่ได้เลย

**เสีย:** ผู้อ่านอาจยังเข้าใจว่านี่คือการอนุญาต ข้อความเตือนจึงอยู่ใต้ผลลัพธ์ทุกกรณี รวมถึงกรณีที่ไม่พบผังด้วย

**ข้อจำกัดที่บันทึกไว้:**

- ครอบคลุม 75 จาก 77 จังหวัด (ไม่มีกรุงเทพมหานครและนนทบุรีในบริการนี้) และบางบริการหยุดให้บริการเป็นครั้งคราว
  กรณีจังหวัดที่ไม่มีบริการจะรายงานว่า "ยังไม่ได้เผยแพร่" ไม่ใช่ error
- การค้นใช้การตรวจว่าจุดอยู่ในรูปหลายเหลี่ยมจริง (`tolerance=0`) ไม่ใช่การค้นแบบมีรัศมี จุดที่ตกร่องถนน
  แม่น้ำ หรือทางรถไฟ จะได้คำตอบว่า "ไม่อยู่ในผัง" ซึ่งตรงกับที่ระบบของกรมฯ เองตอบ จากการสุ่ม 20 จุดทั่วประเทศ
  มี 17 จุดที่ได้โซน และ 3 จุดที่ตกร่อง — ขยับไม่กี่สิบเมตรก็พบโซน
- ผังรุ่นเก่าไม่มีฟิลด์ชื่อไทย (`PL_DESC`) ระบบจึงอ่านชื่อจากหน้า legend ของผังนั้นแทน
  ถ้าอ่านชื่อไม่ได้เลย จะไม่แสดงรายการนั้น ซึ่งเป็นข้อจำกัดที่ยอมรับไว้ตอนนี้
- ฟิลด์ `PL_FAR_MAX`, `PL_BCR_MAX`, `PL_DENS_*` มีอยู่ในข้อมูลบางผัง แต่ **ยังไม่ถูกนำมาใช้**
  ค่าที่พบในผังที่ตรวจเป็น 0 ทั้งหมด การนำ FAR/BCR ไปคำนวณต้องผ่าน economic component ที่มีเวอร์ชัน
  และ activation gate ตามปกติ ไม่ใช่ทางนี้

## ทางเลือกที่ไม่เลือก

- **เอาโซนไปตัดสิน FEASIBLE/ไม่ FEASIBLE ให้อัตโนมัติ** — ต้องมีชุดกฎที่ผ่าน `ACADEMIC_REVIEWED`
  พร้อมบันทึกผู้รีวิว และต้องจับคู่ "กิจการ" ในข้อกำหนดกับ activity id ของระบบอย่างครบถ้วน
  ทำแบบเร่งด่วนคือการแต่งผลทางกฎหมายขึ้นมา
- **ดึงโพลิกอนมาลงฐานข้อมูลเอง** — ฐานข้อมูล Supabase เหลือที่ประมาณ 121 MB หลังตัดข้อมูลแปลงที่ดิน
  และข้อมูลผังเมืองทั้งประเทศใหญ่กว่านั้นมาก อีกทั้งกรมฯ แก้ไขผังตามกฎกระทรวงที่ประกาศใหม่เรื่อย ๆ
  การเรียกสดจึงตรงกับต้นทางเสมอ
- **วาดสีเอง** — เท่ากับ implement สัญลักษณ์ของกฎกระทรวงขึ้นใหม่ และผิดในจุดที่ไม่มีใครสังเกต

## Addendum, 2026-10-07 — the map moves to the result too

The owners asked for "แผนที่ + สีผังเมือง ไปไว้ในหน้าผลลัพธ์ด้วย". The quoted ข้อกำหนด and ข้อห้าม
were already there; the colours were not, and they answer a different question from the words —
what is next to this land, how far the zone reaches, whether the plot sits in the middle of a zone
or on its boundary. That question was only answerable on the form that produced the run, which the
reader has left by the time they are reading the result.

The result's map is **read-only**: no click places a pin, the marker cannot be dragged, and there is
no place search. The run has already been computed from this point, and offering a correction here
that silently does not apply to the analysis below it would be worse than offering none. The
overlay starts **on**, unlike on the form, because showing it is the only reason this map exists,
and the key below it starts **unfolded**, because a map drawn in those colours with the key folded
is a page of pink and green.

The tile layer itself is now one module shared by both maps, so the projection arithmetic cannot
drift between them.
