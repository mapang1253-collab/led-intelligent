# แหล่งข้อมูล: ราคาประเมินอาคารชุด (กรมธนารักษ์)

> เอกสารนี้เป็น **หลักฐานที่มีวันที่** ไม่ใช่การอนุญาตให้เปิดใช้งาน การ activate ต้องผ่าน gate ใน
> `docs/implementation-plan.md` §4 และต้องมีบันทึกการตรวจทานที่ระบุชื่อผู้ตรวจเสมอ

ตรวจสอบกับไฟล์จริงเมื่อ **17 กันยายน 2569**

## 1. ทำไมแหล่งนี้ถึงต่างจากแหล่งอื่นในระบบ

ทุกแหล่งข้อมูลที่ระบบนี้ใช้อยู่อธิบาย **พื้นที่** — ประชากรของตำบล รายได้ของจังหวัด
ราคาประเมินสิ่งปลูกสร้างรายประเภทของจังหวัด

แหล่งนี้อธิบาย **อาคารจริงที่มีชื่อ** 7,906 แห่ง แต่ละแห่งพกรหัสพื้นที่ที่ตัวเองตั้งอยู่มาด้วย
จึงเป็นแหล่งเดียวที่ทำให้ระบบตอบได้ว่า "ในตำบลที่คุณเลือก มีอสังหาอะไรบ้าง และราคาประเมินเท่าไหร่"

นี่คือเหตุผลเดียวกันที่ทำให้มันอันตรายกว่าแหล่งอื่น: ตัวเลขที่ติดอยู่กับชื่ออาคารจริง
ชวนให้อ่านว่าเป็นราคาตลาดมากกว่าตัวเลขที่ติดอยู่กับชื่อจังหวัดมาก

## 4. การจับคู่กับเขตการปกครอง — จุดที่ต่างจากข้อมูลประชากร

ไฟล์นี้ให้ **รหัส** ไม่ใช่แค่ชื่อ และรหัสประกอบกันเป็นรหัสมาตรฐาน 6 หลักได้ตรง ๆ

```
CHANGWAT_CODE=10 · AMPHUR_CODE=1 · TUMBON_CODE=2  →  100102  →  แขวงวังบูรพาภิรมย์
```

ต้องเติมศูนย์หน้าให้ครบสองหลักก่อน มิฉะนั้น `10+1+2` จะกลายเป็น `1012` ซึ่งเป็นคนละที่

**ผลการทดสอบจับคู่กับ `reference.administrative_area` (17 ก.ย. 2569):**

| | แถว | สัดส่วน |
|---|---|---|
| จับคู่ถึงระดับ**ตำบล/แขวง**ได้ | 117,488 | **96.2%** |
| ลงได้แค่ระดับ**อำเภอ/เขต** | 4,585 | 3.8% |
| จับคู่ไม่ได้เลย | 39 | 0.03% |

เทียบกับข้อมูลประชากรที่จับคู่ด้วยชื่อแล้วเสีย 135 ตำบลจากชื่อซ้ำ — การจับคู่ด้วยรหัสไม่มีปัญหานั้น

รหัสตำบล 33 จาก 556 รหัสไม่มีคู่ใน `geothai` (เช่น `100551`, `100654`, `100951` — รูปแบบลงท้าย `51`
บ่งชี้ว่าเป็นรหัสพิเศษหรือรหัสเดิมก่อนการแบ่งเขต) แถวเหล่านั้นถูกวางไว้ที่ระดับอำเภอ **ไม่ใช่เดาลงตำบลใดตำบลหนึ่ง**

## 5. การแปลงเป็น Observation

แหล่งให้ราคา **แยกรายชั้น** ของแต่ละประเภทการใช้ อาคารหนึ่งจึงมีหลายสิบแถวที่ต่างกันแค่ชั้นและไม่กี่ร้อยบาท

- แสดงทุกแถว → ผู้อ่านจมกับตัวเลข (บางตำบลมีถึง 5,573 แถว)
- เฉลี่ยทุกชั้น → **สร้างตัวเลขที่กรมธนารักษ์ไม่เคยประกาศ** — ต้องห้ามตาม ADR 0002

วิธีที่ใช้: ยุบชั้นเป็น **ช่วงราคาที่แหล่งครอบคลุมจริง** (ต่ำสุด–สูงสุด) หนึ่ง Observation
ต่อ **อาคาร × ประเภทการใช้** พร้อมจำนวนชั้นที่อยู่เบื้องหลังติดไปกับชื่อกลุ่ม เพื่อให้ย้อนตรวจกับไฟล์ได้

| | |
|---|---|
| Observation ที่ได้ | **13,703** (จาก 122,112 แถว) |
| เป็นช่วงราคา | 8,882 |
| เป็นค่าเดี่ยว (ชั้นเดียว) | 4,821 |
| ระดับตำบล/แขวง | 13,432 · ระดับอำเภอ/เขต 271 |
| `epistemic_status` | `OBSERVED` เมื่อมีชั้นเดียว · `DERIVED` เมื่อยุบหลายชั้นเป็นช่วง |

ค่าช่วงถูกเก็บลง `value_low`/`value_high` ใน `evidence.observation_value` ตามที่ schema
ออกแบบไว้ตั้งแต่ migration 0003 (*"a range is not a scalar and must not be flattened into one"*)

## 6. สิ่งที่ห้ามให้ตัวเลขนี้กลายเป็น

> **ราคาประเมินเพื่อการจัดเก็บภาษี ไม่ใช่ราคาซื้อขายในตลาด และมักต่ำกว่าราคาตลาด**

ข้อความนี้ติดอยู่กับ **ทุก Observation** ไม่ใช่แค่กับหน้าจอที่ล้อมรอบมัน

- ห้ามใช้แทนราคาซื้อขายจริงหรือราคาเสนอขาย
- ห้ามใช้ประเมินมูลค่าห้องชุดใดห้องชุดหนึ่งโดยเฉพาะ — ราคาต่างกันตามชั้นและตำแหน่งห้อง
  ซึ่งช่วงราคาบอกไม่ได้ว่าห้องไหนอยู่ตรงไหนในช่วง
- ห้ามใช้เป็นหลักฐานว่ามีดีมานด์หรือไม่มีดีมานด์ในพื้นที่
- ห้ามนำราคาของอาคารต่าง ๆ มาเฉลี่ยเป็น "ราคาอาคารชุดในตำบลนี้"

## 7. ข้อจำกัดที่ต้องแสดงต่อผู้ใช้

1. **ครอบคลุม 51 จาก 77 จังหวัด** — ไม่มีข้อมูลไม่ได้แปลว่าไม่มีอาคารชุด
2. **อาคารชุดเท่านั้น** ไม่มีบ้านเดี่ยว ทาวน์เฮาส์ ที่ดินเปล่า หรืออาคารพาณิชย์ที่ไม่ได้จดทะเบียนอาคารชุด
3. **ช่วงราคาไม่บอกว่าชั้นไหนราคาเท่าไหร่** — ผู้ใช้ที่ต้องการราคาห้องของตนเองต้องดูบัญชีต้นฉบับ
4. **รอบบัญชีประเมิน** ไฟล์ลงวันที่ 2024-08-05 รอบใหม่ พ.ศ. 2570–2573 จะมีผล 1 ม.ค. 2570
5. **ไม่มีพิกัด** ไฟล์ไม่มีละติจูด/ลองจิจูด — ระบบจึงลิงก์ไปแผนที่ด้วย *การค้นหาจากชื่อ* เท่านั้น
   ไม่ใช่การปักหมุด และไม่อ้างว่ารู้ตำแหน่งที่แน่นอน

## 9. คำถามที่ยังไม่มีคำตอบ

1. รหัสตำบล 33 รหัสที่ไม่มีคู่ใน geothai คือการแบ่งเขตรุ่นใด
2. `USE_CATG` 987 ค่าที่เป็นข้อความอิสระ ควรจัดกลุ่มหรือไม่ — ปัจจุบัน**ไม่จัด** เพื่อไม่ให้ตีความแทนแหล่ง
3. `BUILD_NAME` (ชื่ออาคารย่อยในโครงการ) ยังไม่ได้ใช้ อาคารเดียวกันหลายตึกจึงรวมอยู่ในกลุ่มเดียว
